TAPSIHAN SA ASUKARERA - BACKEND MIGRATION STATUS

This package is the first backend-integration phase built on the supplied
tapsihan_inventory database schema.

CONNECTED IN THIS PHASE
- Inventory Catalog: inventory items are loaded from MySQL and add/edit/archive
  changes are saved to inventory_items.
- Supplier module: assignments load from MySQL and add/edit/remove changes are
  saved through Supplier/suppliers.php to suppliers and item_suppliers. The endpoint
  uses a transaction and reports errors instead of claiming an unsaved change
  succeeded.
- System Audit Log: actions that call addAuditLog() are also written to the
  audit_logs table through api/audit.php.
- Audit Log page reads the persisted audit_logs records from MySQL.

IMPORTANT
- Other module records (portion mappings, shifts, stock counts, restocks,
  waste/spoilage, and reconciliations) still use their existing browser storage
  in this phase. Their audit events may now be saved to MySQL, but that does
  not mean their full transaction records have been migrated yet.
- No database schema changes are required for this phase.
- Keep the current database backup before testing.

SETUP / TEST
1. Copy the updated project files into the same project root used by XAMPP.
2. Check config/config.php and make sure the database settings match your local
   tapsihan_inventory database.
3. Start Apache and MySQL in XAMPP.
4. Open the site through http://localhost/<your-folder>/Login/login.html.
   Do not open the HTML files directly from the filesystem.
5. Log in, open Inventory Catalog, and test add/edit/archive.
6. Open Suppliers and test assigning, editing, removing one supplier, and
   removing all suppliers.
7. In phpMyAdmin, inspect inventory_items, item_suppliers, suppliers, and
   audit_logs to verify that the changes are saved.

If the Inventory Catalog cannot reach MySQL, it will show a warning and retain
the browser copy rather than silently claiming the database save succeeded.
